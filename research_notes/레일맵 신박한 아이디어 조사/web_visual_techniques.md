# Web visual and interactive techniques for 레일맵 (MapLibre GL JS + vanilla JS, static hosting)

Project context checked locally: `package.json` pins `maplibre-gl` `^6.16.0`; the game already uses `map.flyTo` (station focus in `src/ui/app.js`, `src/ui/search.js`, `src/ui/noticeLog.js`) and `CompressionStream('deflate-raw')` for share links (`src/game/share.js`). It does not yet use `canvasContextAttributes`/`preserveDrawingBuffer`, `setProjection`, or `easeTo`. Everything below is static-site compatible unless marked.

## Camera and presentation (flyTo/easeTo, free camera, pitch/2.5D, globe, 3D buildings, follow-a-train, cinematic tours)

### Takeaway
MapLibre GL JS ships everything needed for cinematic camera work without plugins: `flyTo`/`easeTo` (with `roll`, `padding`, and `essential` for reduced-motion), `cameraForBounds`/`fitBounds`, free-camera helpers (`calculateCameraOptionsFromTo`, `calculateCameraOptionsFromCameraLngLatAltRotation`), globe projection (v5+), and `fill-extrusion`. For a flat art style, the best fits are a 2D "follow this train" camera, slow `easeTo` tours over the network, and a globe used only as a zoomed-out intro on the start screen. Strong pitch and 3D buildings fit less well because extruded walls look shaded.

### Cited Findings
- `flyTo(options, eventData)` "animates camera changes along a flight-like curve". `easeTo` animates center, zoom, bearing, pitch, roll, or padding. Both respect reduced-motion users (the transition is skipped unless `essential: true`) — [MapLibre Map API](https://maplibre.org/maplibre-gl-js/docs/API/classes/Map/)
- `cameraForBounds(bounds, options)` returns center/zoom/bearing without moving the map. `fitBounds` resets bearing to 0 — [MapLibre Map API](https://maplibre.org/maplibre-gl-js/docs/API/classes/Map/)
- Free-camera helpers exist in GL JS. `calculateCameraOptionsFromTo(from: LngLat, altitudeFrom, to: LngLat, altitudeTo?)` computes a camera looking from one point to another. `calculateCameraOptionsFromCameraLngLatAltRotation(cameraLngLat, cameraAlt, bearing, pitch, roll?)` turns a camera position plus rotation into CameraOptions (pass the result to `jumpTo`) — [MapLibre Map API](https://maplibre.org/maplibre-gl-js/docs/API/classes/Map/); same pattern documented in [MapTiler SDK Camera](https://docs.maptiler.com/sdk-js/api-reference/classes/Externals.Camera/)
- MapOptions include `maxPitch` (default 60, range 0–180), `roll` (initial roll angle), `elevation`, `centerClampedToGround` (set false to keep the camera above ground at pitch over 90°) — [MapLibre MapOptions](https://maplibre.org/maplibre-gl-js/docs/API/type-aliases/MapOptions/)
- Official camera examples (good copy-paste starting points): "Fly to a location", "Slowly fly to a location", "Jump to a series of locations", "Animate map camera around a point", "Customize camera animations", "Fly to a location based on scroll position" (scrollytelling tour), "Walk around a map in first person", "Navigate the map with game-like controls", "Set pitch and bearing" — [MapLibre examples index](https://maplibre.org/maplibre-gl-js/docs/examples/) (e.g. [animate-map-camera-around-a-point](https://maplibre.org/maplibre-gl-js/docs/examples/animate-map-camera-around-a-point/), [fly-to-a-location-based-on-scroll-position](https://maplibre.org/maplibre-gl-js/docs/examples/fly-to-a-location-based-on-scroll-position/))
- Globe rendering was added in MapLibre GL JS v5. Enable it with `map.setProjection({ type: 'globe' })` inside `map.on('style.load', …)`. Calling it before the style loads throws. Projection can also be set in the style JSON — [MapLibre globe example](https://maplibre.org/maplibre-gl-js/docs/examples/display-a-globe-with-a-vector-map/); [Stadia Maps globe tutorial](https://docs.stadiamaps.com/tutorials/3d-globe-view-with-maplibre-gl-js/)
- Related globe examples: "Display a globe with an atmosphere", "Display a globe with a fill extrusion layer", "Zoom and planet size relation on globe" — [MapLibre examples index](https://maplibre.org/maplibre-gl-js/docs/examples/)
- One binding (Flutter) shows projection set by an expression that fades from globe to mercator by zoom. This is not confirmed for the JS API — [MapLibre Flutter: Globe, Terrain and Sky](https://maplibre.org/flutter-maplibre-gl/advanced/globe-terrain-sky/)
- 3D buildings: the `fill-extrusion` layer has `fill-extrusion-height`, `-base`, `-color`, `-opacity`, `-vertical-gradient`, `-pattern`, `-translate`, and a newer `fill-extrusion-rounded-corner-distance`. `fill-extrusion-height` supports data-driven, `feature-state`, and interpolate expressions and is transitionable (so buildings can "rise") — [MapLibre style spec: layers](https://maplibre.org/maplibre-style-spec/layers/); examples "Display buildings in 3D", "Fill extrusion rounded corners" — [MapLibre examples index](https://maplibre.org/maplibre-gl-js/docs/examples/)
- Real follow-a-train example: Mini Tokyo 3D (open source, MIT, real-time Tokyo trains). Clicking a train turns on "Tracking Mode" and clicking empty map turns it off. v3.2.0 added the modes `position` (keep current distance/direction/angle, the default), `back`, `topback`, `front`, `topfront`, `drone`, and `bird`, plus "helicopter/drone" 360° orbits around the vehicle — [Mini Tokyo 3D configuration docs](https://minitokyo3d.com/docs/master/user-guide/configuration.html); [v3.2.0 release](https://github.com/nagix/mini-tokyo-3d/releases/tag/v3.2.0); [repo](https://github.com/nagix/mini-tokyo-3d)

### Inferences
- **Follow a train (2D)**: on each animation frame, after the train source `setData`, call `map.jumpTo({ center: trainLngLat, bearing: optionalHeading })`. Turn it on by clicking a train number label and off with a drag/Esc. Cost is low: the game already redraws every frame, and `jumpTo` just moves the camera. Effort is about 1 day. Flat-style fit is excellent. Turning bearing with the train heading ("cab view") may cause motion sickness, so offer north-up as the default (inferred).
- **Cinematic network tour / "opening ceremony"**: queue `flyTo`/`easeTo` calls on the `moveend` event, or chain promises. Order the stops by line, then by station, and use `cameraForBounds(lineBBox, { padding })` for each line. Play it slowly (`speed` ≈ 0.3–0.6, `curve` ≈ 1.2). Pass `essential: false` so reduced-motion users skip it. Effort is about 1–2 days, cost is low, and it fits the flat style well.
- **Pitch/2.5D**: a light pitch (20–40°) with an orbit (`rotateTo` loop, or the "animate camera around a point" example) gives a "diorama" photo look and keeps the flat style, because the map stays flat and only the camera tilts. Effort is minutes. Extra tiles load at the horizon, so it costs moderate GPU/network at high pitch. The `maxPitch` default of 60 is fine.
- **3D buildings**: `fill-extrusion` with a single beige `fill-extrusion-color` and `fill-extrusion-vertical-gradient: false` is the closest to flat. MapLibre still lights walls through the light, so faces get different shades. That conflicts with the "no shadows" art rule; use it only in photo mode, if at all. OpenFreeMap tiles carry `render_height` for buildings (from general knowledge of OpenMapTiles; not verified in this research). Cost is moderate to high with dense buildings.
- **Globe**: best used on the start screen as a slowly spinning globe with the 12 cities as dots. Clicking a city does `flyTo` into it, then switches to mercator. Globe conflicts with the game's mercator-based station sizing, so do not use it in gameplay. The project is on v6.16, so globe is available. Effort is about 1–2 days, mainly the transition.
- No plugin or server is needed for any camera technique.

### Gaps
- I did not verify the exact `setSky`/`setLight` APIs or whether the light can be set to ambient-only for fully flat extrusions (the Map API page was truncated past `getFeatureState`).
- The Mini Tokyo 3D camera math for its follow modes was not documented in the sources I read; I did not read its source code.
- I did not confirm whether projection-by-zoom expressions (globe→mercator) are supported in GL JS v6.

## Time and motion (timelapse replay, animated line growth, day/night tint, rush-hour pulses)

### Takeaway
All of these can run in the browser from data the game already has. A timelapse replays a recorded edit log (the undo history is already a good start). Line growth uses `line-gradient` with `lineMetrics: true` (or trimming the GeoJSON each frame). Day/night is a palette interpolation via `setPaintProperty`. Rush-hour pulses are trains as data with `feature-state` or a per-frame `setData`. deck.gl's `TripsLayer` is the reference look for glowing train trails, but it adds a heavy dependency the game does not need.

### Cited Findings
- `line-gradient` exists, but "can only be used with GeoJSON sources that specify `lineMetrics: true`". It is not data-driven, and `line-dasharray`/`line-pattern` disable it (GL JS since 0.45) — [MapLibre style spec: layers](https://maplibre.org/maplibre-style-spec/layers/)
- `line-dasharray` is transitionable and gained data-driven support in GL JS 5.8.0 — [MapLibre style spec: layers](https://maplibre.org/maplibre-style-spec/layers/)
- Official examples for motion: "Animate a line" (grow a line by appending coordinates and calling `setData`), "Animate a point along a route", "Animate a point", "Create a gradient line using an expression", "Create a gradient dashed line using an expression", "Animate an icon on the GPU", "Add an animated icon to the map" — [MapLibre examples index](https://maplibre.org/maplibre-gl-js/docs/examples/) (e.g. [animate-a-line](https://maplibre.org/maplibre-gl-js/docs/examples/animate-a-line/), [create-a-gradient-line-using-an-expression](https://maplibre.org/maplibre-gl-js/docs/examples/create-a-gradient-line-using-an-expression/))
- Paint properties marked transitionable (e.g. `fill-color`, `line-dasharray`, `fill-extrusion-height`) animate between values automatically; layout properties do not — [MapLibre style spec: layers](https://maplibre.org/maplibre-style-spec/layers/)
- deck.gl `TripsLayer` "renders animated paths that represent vehicle trips". `currentTime` is the playhead and `trailLength` sets how much of the path behind the playhead stays visible; you animate it by advancing `currentTime` each frame (the Google sample loops it with modulo 1800, `trailLength` 180) — [deck.gl TripsLayer docs](https://deck.gl/docs/api-reference/geo-layers/trips-layer); [Google Maps + deck.gl TripsLayer sample](https://developers.google.com/maps/documentation/javascript/examples/deckgl-tripslayer)
- MapLibre has deck.gl integration examples ("Toggle deck.gl layer", "Create deck.gl layer using REST API") — [MapLibre examples index](https://maplibre.org/maplibre-gl-js/docs/examples/)
- Precedent for a 24-hour time loop: Conductor (mta.me) "continues accelerating through a 24-hour loop" of NYC subway schedule data — [Hyperallergic](https://hyperallergic.com/alexander-chen-conductor-www-mta-me); [Vimeo](https://vimeo.com/19372180)

### Inferences
- **Timelapse replay of building**: record `{ t: gameDate, op, payload }` for every `change()` call (the project already routes all mutations through `change()` in `game/history.js`). To replay, start from an empty network and re-apply ops on a timer, about 0.3 s per op. The camera can `easeTo` the bounding box of each op, and each new segment can draw in with the growth effect below. A replay of the network *as built* needs the log saved in the save file (it can be compact: op type + ids). For networks without a log (presets, shared links), a "fake timelapse" could order tracks by BFS from the first station, or line by line. Effort is 2–4 days, the cost is negligible, and it fits the flat style well. Pair it with video export (Photo section) for a shareable "my city in 30 seconds" clip.
- **Animated line growth on opening**: when a route opens, put that route's line in a temporary GeoJSON source with `lineMetrics: true`. Animate `line-gradient` as `['step', ['line-progress'], color, p, 'transparent']`, with `p` from 0→1 over about 1.2 s via `setPaintProperty` per frame. Trimming the coordinate array with `turf.lineSliceAlong` and calling `setData` also works and supports dashes. Effort is about 1 day. It is cheap because it touches only one short line.
- **Day/night cycle tint**: interpolate the existing beige palette toward the control-room palette (`CONTROL_ROOM_PALETTE` in `map/style.js`) by game time of day. Throttle the `setPaintProperty` calls on the background, land, water, and road layers to about once per game hour, because each call triggers a style update; do not run them every frame. A flatter alternative is a single full-screen `background` color shift plus station windows "lighting up" (accent yellow dots at night). Effort is 1–2 days, the cost is low if throttled, and it is fully flat-compatible.
- **Rush-hour pulses**: the game uses daily demand, so a "virtual clock" can show 7–9 and 18–20 peaks. Possible looks: train label size, a pulse ring around busy stations (a circle layer whose `circle-radius` comes from a per-frame phase in feature properties), or congestion color breathing. Effort is about 1 day, cheap if done in the existing per-frame train `setData`.
- **Glowing train trails without deck.gl**: keep the last N positions per train in the train GeoJSON as a short LineString with `line-gradient` from opaque to transparent. This mimics TripsLayer in about 50 lines. Watch the cost: 800 trains × trail points per frame is heavier than points alone, so cap the trail at 4–6 points and enable it only when zoomed in or in photo mode. Gradient fades are technically a gradient; keep them subtle or use stepped opacity to respect the flat rule.

### Gaps
- No `line-trim-offset` property appeared in the MapLibre style spec content I read (it exists in Mapbox GL). Treat it as unavailable and use `line-gradient` or `line-progress` steps instead. The second part of the spec page was not read.
- I did not measure `setPaintProperty` cost per call on MapLibre v6.

## Data visualization (isochrones, passenger flows/desire lines, coverage heatmaps, animated passenger dots, catchment maps)

### Takeaway
The best-known transit isochrone maps (Mapnificent, Chronotrains) show "where can I get in N minutes from here" on hover or click. The game can compute this fully client-side, because it already has a station/route graph with waits and transfers (`game/tripFinder.js`). Draw the result as station circles with radius = remaining time × walking speed, merged visually by drawing all circles in one fill layer (no polygon union needed). Coverage heatmaps (the `heatmap` layer) and passenger desire lines (one `line` layer weighted by trips) also work without a server.

### Cited Findings
- Chronotrains is an interactive Europe map that shows "how far you can travel by train" in up to 8 hours; hovering a starting city shows the reachable area. It uses estimated travel times from Deutsche Bahn data via Direkt Bahn Guru. Side project by Benjamin Tran Dinh and Sarah Mamy. An older GitHub description says 5 h, so the time window changed between versions — [Chronotrains About](https://chronotrains-com.onrender.com/about); [GitHub](https://github.com/chazgorman/chronotrains)
- Mapnificent shows areas you can reach with public transport in a given time, built from GTFS timetables. A separate `mapnificent_generator` converts GTFS into a Mapnificent protobuf, and a `mapnificent.js` client repo exists. The site is Jekyll-built (static) — [Mapnificent GitHub org](https://www.github.com/mapnificent); [mapnificent repo](https://github.com/mapnificent/mapnificent); [Atlas Obscura on isochrone maps](https://www.atlasobscura.com/articles/isochrone-maps-commutes-travel-times)
- An isochrone follows the network rather than a straight radius, so its shape reflects how people actually move — [Wikipedia: Isochrone map](https://en.wikipedia.org/wiki/Isochrone_map); [Stadia Maps: isochrones](https://stadiamaps.com/learn/isochrones/)
- MapLibre has a `heatmap` layer (GL JS since 0.41) and an official example "Create a heatmap layer" — [MapLibre style spec](https://maplibre.org/maplibre-style-spec/layers/); [example](https://maplibre.org/maplibre-gl-js/docs/examples/create-a-heatmap-layer/)
- "Create a hover effect" demonstrates `setFeatureState` for hover highlighting without re-uploading data — [MapLibre example](https://maplibre.org/maplibre-gl-js/docs/examples/create-a-hover-effect/)
- Animated vehicle/passenger trails are the classic deck.gl `TripsLayer` look — [deck.gl TripsLayer](https://deck.gl/docs/api-reference/geo-layers/trips-layer)

### Inferences
- **Isochrone ("N minutes from here") mode**: on click of a station, run one single-source Dijkstra over the existing station/route graph, including wait time (half headway), transfer penalty, and travel time; `tripFinder.js` already has the priority queue and edge costs. For each reached station with arrival time `t < T`, add a circle feature with radius `(T − t) × 80 m/min` (walking). Render the circles in one `fill` layer with 3–4 time bands (15/30/45/60 min) in stepped beige-to-navy tints, drawing larger bands first. Overlapping same-band circles look like one shape with no union math. Use `turf.circle` for real meter radii, or a `circle` layer with radius converted from meters at zoom (cheaper; circles are flat by nature). Add a hover-to-preview like Chronotrains. Performance: Dijkstra over 300–450 stations is under 1 ms to a few ms. Building 450 × 4 circle polygons (64 vertices) is about 115k vertices, which is fine. Effort is 2–3 days. This is probably the single most "wow" item and fits the "joy of building" goal: players see their new line expand the 30-minute blob. A "before/after" diff of the blob when a line is added is a strong reward moment.
- **Coverage map**: a `heatmap` layer from building centroids or the existing catchment cells, weighted by population and masked by distance to the nearest station. Alternatively, a flat stepped `fill` grid (served/unserved). Heatmap's built-in color ramp is a gradient; a stepped `heatmap-color` with `step` keeps the flat look. Effort is 1–2 days, cost is low to moderate.
- **Desire lines / passenger flow**: from the demand matrix (station pairs × daily riders), draw the top K pairs as straight or curved lines with `line-width` from riders. Unserved desire, such as pairs connected only by long transfers, can be shown in the accent yellow to suggest "build here". Keep K ≤ 200 for readability. Effort is 1–2 days. The data already exists in `demand.js`/the worker.
- **Animated passenger dots**: on the existing per-frame train source, add small dots that hop from station to train on arrival. Driving this from the daily totals is "ambient", not a true agent simulation. Keep the count bounded (e.g. ≤ 300 dots) to protect the 800-train budget.
- **Line load diagram**: segment width proportional to load (a "Sankey on the map") via data-driven `line-width` on track segments. This is cheap because the congestion coloring already computes per-segment load.

### Gaps
- I could not find a description of Mapnificent's exact client algorithm (whether circles are drawn in a canvas or worker). From general knowledge it draws walking circles around reached stations on a canvas, but the sources I fetched did not confirm this, so treat it as unverified.
- I did not find a source for "Transit app" visualizations specifically.

## Photo mode and exports (hide UI, framing, high-res PNG, poster layouts, GIF/video, share cards)

### Takeaway
High-resolution map stills are doable client-side. Either create the map with `canvasContextAttributes: { preserveDrawingBuffer: true }` (or read the canvas inside the `render` event), or render an offscreen hidden map at a higher `pixelRatio` and read `getCanvas().toBlob()`. Video works with `canvas.captureStream(fps)` + `MediaRecorder`; check `MediaRecorder.isTypeSupported()` first, because WebM vs MP4 support varies by browser. `@watergis/maplibre-gl-export` is a ready-made control for PNG/JPG/SVG/PDF at chosen DPI and page size.

### Cited Findings
- In current MapLibre, `preserveDrawingBuffer` is not a top-level option. It lives inside `canvasContextAttributes`, whose defaults are `antialias: false`, `powerPreference: 'high-performance'`, `preserveDrawingBuffer: false`, `failIfMajorPerformanceCaveat: false`, `desynchronized: false`, `contextType: 'webgl2'` — [MapLibre MapOptions](https://maplibre.org/maplibre-gl-js/docs/API/type-aliases/MapOptions/)
- `pixelRatio` MapOption sets the canvas size to container size × ratio (default `devicePixelRatio`) — [MapLibre MapOptions](https://maplibre.org/maplibre-gl-js/docs/API/type-aliases/MapOptions/)
- `getCanvas()` returns the map's `<canvas>` — [MapLibre Map API](https://maplibre.org/maplibre-gl-js/docs/API/classes/Map/)
- `attributionControl` can be configured (`compact`, `customAttribution`) or disabled. Exported maps should still carry data attribution — [MapLibre MapOptions](https://maplibre.org/maplibre-gl-js/docs/API/type-aliases/MapOptions/); [@watergis/maplibre-gl-export (npm)](https://npmjs.com/package/%40watergis%2Fmaplibre-gl-export)
- `@watergis/maplibre-gl-export` adds a control that exports PDF and images (jpg, png, svg, pdf), with page size, orientation, DPI, a crosshair for centering, and a printable-area overlay. It is forked from mapbox-gl-export. npm lists 3.8.4 and Yarn lists 4.1.0, so check the latest — [npm](https://npmjs.com/package/%40watergis%2Fmaplibre-gl-export); [Yarn](https://classic.yarnpkg.com/en/package/@watergis/maplibre-gl-export); [mapbox-gl-export (merged)](https://github.com/watergis/mapbox-gl-export)
- Canvas video: `canvas.captureStream(fps)` → `MediaRecorder`; the Theodo guide uses 30 fps. As of 2022, MediaRecorder could not write MP4 in Chrome/Safari, and ffmpeg.wasm can convert WebM→MP4 in the browser — [Theodo: saving canvas animations (2023)](https://blog.theodo.com/2023/03/saving-canvas-animations)
- Safari 18.4 (March 2025) added WebM recording (VP8/VP9 + Opus); Safari 14.1–18.3 only recorded MP4/AAC. Chrome writes MP4 only where an OS encoder exists, so call `MediaRecorder.isTypeSupported()` — [api.video MediaRecorder guide](https://api.video/blog/tutorials/building-record-a-video-the-mediarecorder-api/) (secondary source; verify on MDN/caniuse)
- Web Share API with files: build a `File` from a PNG blob, check `navigator.canShare({ files })`, then `navigator.share(...)`; it needs HTTPS. Support listed: Chrome 128, Edge 93, Safari 12.1, Firefox only behind a flag. Fall back to a download — [web.dev: How to share files](https://web.dev/patterns/files/share-files)

### Inferences
- **Photo mode** (the H key already hides UI): add `[사진]`, which does the following.
  1. Pause or slow time and hide UI.
  2. Show framing guides (rule of thirds, 16:9 / 1:1 / 9:16 crops as CSS overlays).
  3. Offer optional pitch/bearing sliders (`easeTo`).
  4. Offer a "poster" frame: a title, the line legend, and a scale, reusing `diagramExport.js` patterns.
- **High-res still**: option A is to set `preserveDrawingBuffer: true` at creation. That costs a little GPU memory and can slightly hurt performance, because the browser must keep the buffer, so turn it on only for a photo map. Option B (preferred) needs no global flag: inside `map.once('render', () => map.getCanvas().toBlob(...))` after `triggerRepaint()`, the buffer is still valid. Option C, for posters, is a hidden offscreen `div` sized e.g. 4000×4000 CSS px, or the same container with `pixelRatio: 3`. Build a second `new maplibregl.Map({ style: map.getStyle(), center, zoom, bearing, pitch, interactive: false, pixelRatio: N })`, wait for `idle` (fine here because no trains move in it), call `toBlob`, then `remove()`. Large canvases hit WebGL max texture/drawing-buffer limits (often 8k–16k px), so cap the size by `gl.getParameter(gl.MAX_RENDERBUFFER_SIZE)`. Effort is 1–3 days. Composite the map + title/legend on a 2D canvas, as the existing diagram PNG export already does.
- **Short video/GIF of trains running**: `const stream = map.getCanvas().captureStream(30); new MediaRecorder(stream, { mimeType: pick(['video/mp4;codecs=avc1','video/webm;codecs=vp9','video/webm']) })`. Record 10–20 s while the camera does a slow `easeTo` orbit. The DOM station labels (HTML speech bubbles) will not appear, because captureStream only records the WebGL canvas. Either switch labels to a MapLibre symbol layer during recording, or composite a 2D canvas per frame (draw the map canvas + labels) and capture that canvas instead. To add the game's music, use `AudioContext.createMediaStreamDestination()` and add its track to the stream. Effort is 2–4 days. CPU cost while recording is moderate. GIF needs a library (gif.js / gifenc) and is large, so prefer WebM/MP4.
- **Share card**: generate a 1200×630 PNG (like the existing `public/og-image.png` layout) with the city, network stats, and the diagram. Offer `navigator.share` with the file + share link on mobile, and download + copy link on desktop. Dynamic og:image previews for each shared link are impossible without a server: link previews read static HTML meta tags and do not run JS, so every share link shows the same og-image.

### Gaps
- I did not find an authoritative 2025–2026 compatibility table (MDN/caniuse) for MediaRecorder MP4 in Chrome/Firefox; the Safari 18.4 claim comes from a secondary source.
- I did not verify whether MapLibre v6 still renders correctly into a hidden zero-visibility container (it needs non-zero size; `visibility:hidden`/off-screen positioning is the usual trick).
- No official MapLibre "print/export" example exists in the examples index.

## Sound (generative music tied to the network)

### Takeaway
Two proven models exist. Conductor (mta.me) treats each line as a string that is plucked when a train departs. Mini Metro (Disasterpeace) is a sample-triggered sequencer where each line holds one note plus one rhythm, harmony advances as the player edits lines, and passenger events are quantized to a beat grid. Both map directly onto Web Audio scheduling (`AudioContext.currentTime` look-ahead scheduling) and the game's existing pentatonic synth.

### Cited Findings
- Conductor (2011, Alexander Chen) is built in HTML5/JavaScript on the MTA's public schedule data. It uses Vignelli's 1972 map as the visual base, and each train is a plucked note as it departs, running through an accelerating 24-hour loop. The strings are drawn as lines between stations and vibrate when crossed (the visual motif). Ghost trains represent closed routes. The audio came from Freesound.org Creative Commons samples — [Hyperallergic](https://hyperallergic.com/alexander-chen-conductor-www-mta-me); [Vimeo](https://vimeo.com/19372180); [Swiss Miss](https://www.swiss-miss.com/2011/02/conductor-mta-me.html); [Untapped Cities](https://www.untappedcities.com/fun-maps-watch-this-mesmerizing-string-instrument-visualization-of-the-nyc-subway-system/)
- Mini Metro: "Pretty much everything you hear in the game consists of samples that are triggered in real-time." Each city has its own rhythms, harmony (strings of notes defining voice leading), and train engine sounds, and the harmony can change by game week — [Designing Sound interview with Rich Vreeland](https://designingsound.org/2016/02/18/the-programmed-music-of-mini-metro-interview-with-rich-vreeland-disasterpeace)
- Mini Metro lines: each line is tied to one note and one rhythm. Altering a line advances its rhythm to the next option, and the least-recently-altered line swaps the oldest harmony note for the next one. Line tones are made in Serum, with envelopes that change with game speed (the paused game is the most ambient) — [Designing Sound](https://designingsound.org/2016/02/18/the-programmed-music-of-mini-metro-interview-with-rich-vreeland-disasterpeace)
- Mini Metro passengers: their spawn/pickup/dropoff sounds are rhythmically quantized. Different shapes are tied to different times within the in-game hour (on the hour, half hour, quarter). An "Arpeggio" module fans clumped events into a flam and limits events per short window — [Designing Sound](https://designingsound.org/2016/02/18/the-programmed-music-of-mini-metro-interview-with-rich-vreeland-disasterpeace)
- Mini Metro scaling: hard caps (7 lines, 4 locomotives per line, 4 carriages) plus event limits keep the sound from overloading. The sequencer is the update loop of the G-Audio Unity plugin at subdivisions like 16 per bar (FMOD was tried and dropped). Cities vary in swing (New York, St. Petersburg), tuplets (Paris quintuplets/septuplets), and attack (Berlin kick drum) — [Designing Sound](https://designingsound.org/2016/02/18/the-programmed-music-of-mini-metro-interview-with-rich-vreeland-disasterpeace)
- Music scales with the network: a small metro sounds sparse, the music grows with complexity, and speeding up the sim speeds the music — [Kill Screen: designing Mini Metro's soundtrack](https://www.killscreen.com/music-urban-commute-designing-mini-metros-soundtrack/); [Wikipedia: Mini Metro](https://en.wikipedia.org/wiki/Mini_Metro_(video_game))
- Disasterpeace continued the approach in Mini Motorways (procedural harmony and rhythm from road noise) — [Game Developer: Turning road noise into music in Mini Motorways](https://www.gamedeveloper.com/design/turning-road-noise-into-music-mini-motorways); [Disasterpeace blog](https://disasterpeace.com/blog/mini-motorways.talk)

### Inferences
- **"Each line is a voice"**: give each route one pentatonic degree (by route index) and one rhythm pattern from a small table (e.g. `x...x...`, `x..x..x.`). A train *arrival* at a station triggers that route's note, quantized to the next 16th of a global clock (look-ahead scheduler: `setInterval` 25 ms + schedule notes ~100 ms ahead with `osc.start(ctx.currentTime + δ)`). With 800 trains this needs Mini Metro-style caps: at most one note per route per 16th, plus a global voice limit (e.g. 12 voices). Reuse `soundEngine.js` ducking/compressor. Effort is 2–3 days. CPU is low if voices are capped.
- **"Stations as notes"**: map a station's position along its route (index) to scale degree, so a train running end to end plays a melodic phrase. Transfer stations can play a chord of every line's note there. This matches Conductor's "plucked string" feel.
- **Edit-driven harmony** (Mini Metro): advancing the chord when the player edits a line makes building itself musical. This fits the owner's "joy of building" focus best and is cheap.
- **Speed coupling**: at 3× speed the tempo rises; when paused, notes get long envelopes and only ambient drones play (Mini Metro's "paused is most ambient").
- **Conductor-style visual**: in the diagram view, a line segment can "vibrate" (a short sine displacement of its SVG path) when its note plays. This is a lovely, cheap tie between sound and visuals.
- None of this needs audio files or a server.

### Gaps
- I did not find Web Audio-specific talks for Mini Metro (the original runs in Unity), and I did not fetch a web.dev/MDN article on look-ahead scheduling (the "A Tale of Two Clocks" pattern is from general knowledge, not cited here).

## Serverless sharing and galleries (URL limits, QR, file export, Gist/static hosting, curated gallery, share cards)

### Takeaway
URL hashes can carry far more than the game's current 2,000-character warning threshold. Chrome allows 2 MB URLs, but messengers and QR codes are the real constraints. QR codes are practical only for small networks (a QR code holds at most about 2.9 KB of binary data), so a QR of a full real-city share link is not feasible. GitHub Gist is not serverless-friendly: there is no anonymous creation and a token is required, so the robust static options are the hash link, a file export, and a curated gallery bundled into the build as JSON (like the existing presets).

### Cited Findings
- "Chrome limits URLs to a maximum length of 2MB for practical reasons." The omnibox displays only about 32 kB on most platforms — [Chromium URL display guidelines](https://chromium.googlesource.com/chromium/src/+/HEAD/docs/security/url_display_guidelines/url_display_guidelines.md)
- Other browser URL limits are poorly documented and sources conflict (Firefox ~65k chars, Safari ~80k chars per secondary sources). The hash fragment is not sent to the server, so server limits do not apply — [Baeldung: max URL length](https://www.baeldung.com/cs/max-url-length); [Sistrix](https://www.sistrix.com/?p=93492) (secondary, conflicting)
- `CompressionStream` (gzip/deflate/deflate-raw) is Baseline (newly available since May 2023) and also available in workers — [MDN CompressionStream](https://developer.mozilla.org/en-US/docs/Web/API/CompressionStream/CompressionStream) (the game already uses it in `src/game/share.js`)
- Anonymous gist creation via the API was announced for removal in 2018. Old GHE docs say anonymous creation was once allowed. A community wrapper reports that gist raw content URLs are CORS-blocked for browser reads, which means a proxy is needed — [popcode PR #1389](https://github.com/popcodeorg/popcode/pull/1389); [GHE 2.20 gists API](https://docs.github.com/en/enterprise-server@2.20/rest/reference/gists); [@vighnesh153/github-gist (npm)](https://www.npmjs.com/package/@vighnesh153/github-gist)
- Web Share API can share an image file plus text/URL (Chrome 128, Edge 93, Safari 12.1; Firefox only behind a flag) with a download fallback — [web.dev: How to share files](https://web.dev/patterns/files/share-files)

### Inferences
- **Current state is good**: the deflate-raw + delta-coded hash already reaches about 14k chars for the full Seoul network, well under Chrome's 2 MB. The practical risk is messengers truncating long URLs, which the game already warns about at 2,000 chars.
- **QR codes**: a client-side QR library (e.g. `qrcode-generator` or `qrcode`, no server) works for small player networks. The QR spec max at version 40-L is about 2,953 bytes in byte mode (spec knowledge, not cited above). In alphanumeric mode, a base64url hash is not alphanumeric-compatible, so byte mode applies. Rule: show a QR only when the link is ≤ ~1,500 chars, which keeps it scannable on a phone; otherwise hide it with the existing "use [내보내기] file" hint. Effort is half a day, but it adds a dependency (around 10–20 KB).
- **Curated gallery in the build**: add `src/data/gallery/*.json` (the same save format as presets) with a few "beautiful example networks" made by the owner, plus a thumbnail generated by the existing `make-thumbnails.mjs` approach or the diagram PNG export. Show them as cards on the start screen that open as a sandbox. This is zero server and fits GitHub Pages; lazy-load each file like presets (`import()` on click). Effort is 1–2 days.
- **Community gallery without a server**: options in rising order of complexity:
  1. A GitHub Discussions/Issues template where players paste share links. The page links out but does not fetch, so this needs no token.
  2. Players submit PRs adding JSON to a `gallery/` folder, and the owner curates.
  3. A public read-only JSON file in the repo fetched from `raw.githubusercontent.com`, which serves CORS-friendly `Access-Control-Allow-Origin: *` (general knowledge; not verified in this research).

  Writing from the browser to Gist or GitHub needs a user OAuth token, which needs a server-side code exchange (GitHub's device flow also lacks CORS, per general knowledge), so it is out of scope for a static site.
- **Share card + link**: combine the photo-mode PNG with the share link via `navigator.share({ files: [png], text, url })` on mobile; on desktop, download + clipboard copy. Per-link og:image previews are impossible serverless (see Photo section).
- **Embeds**: a read-only "viewer" query flag (e.g. `?view=1#share=…`) that hides the build UI, autoplays trains, and loops a camera tour lets people embed a network in a blog via `<iframe>`. GitHub Pages allows iframing (general knowledge). Effort is about 1 day on top of the tour.

- I did not verify current github.com behavior for unauthenticated `POST /gists` in 2026 or the CORS headers on `api.github.com`/`raw.githubusercontent.com`; I relied on a 2018 PR and an old GHE doc.
- I did not look up the QR capacity table from a primary source (ISO/IEC 18004) during this research; the ~2,953-byte figure is from general knowledge.
